1. Picomatch GHSA-fc5q-39xc-vjpf / CVE-2026-112366 (Highest Priority)

Primary source fact (re-verified now):

github.com/advisories/GHSA-fc5q-39xc-vjpf

High severity, GitHub Reviewed (reviewed ~2 hours ago on 17 Nov 2026), published to GitHub Advisory Database 19 Oct 2026, last updated 17 Nov 2026.
Affected: <= 4.0.7. Patched versions: None.
Description: ReDoS via single-branch repeated extglob patterns (e.g. +(*) or +(*a)); analyzeRepeatedExtglob in lib/parse.js skips them, producing exponential backtracking on short inputs.
References: NVD CVE-2026-112366, open PR #194, source at 4.0.7 parse.js L287–L307, VulnCheck advisory.
Secondary sources (NVD, VulnCheck, OpenCVE) agree on no fixed release. One outlier claimed a fix in an unrelated package version; that is not reflected in the official advisory or picomatch releases (latest 4.0.7 on 24 Aug 2026).

Upstream proposals (open, unmerged as of this access):

PR #194 (opened 13 Aug 2026): focuses on leading-? parsing and adds a mixed-wildcard risky check; related but not a complete fix for the advisory examples.
PR #237 (opened ~22 Oct 2026): proposes rewriting single-branch +(P) / *(P) to remove nested quantifiers while preserving semantics for patterns like +(*)c. Claims timing drop on malicious input; still open.
PR #238 (opened ~22–23 Oct 2026): literalizes single-branch extglobs with leading bare quantifier + trailing content; explicitly notes it leaves +(*) and +(a*) unaddressed. Still open; reviewers flagged incompleteness relative to advisory examples.

Installed versions (supplied fact, last check): 2.3.2, 4.0.4, 4.0.7 (all dev: true). This alone does not prove non-reachability. Development rejected a simplistic guard because valid isMatch('abc','+(*)c') changes. No claim is made here that any proposed patch has passed.
