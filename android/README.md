# Career Finder for Android phones

Native Kotlin / Jetpack Compose client for the verified-applications service. English interface, system-scaled text, right-to-left layout support, light/dark green theme, bottom navigation, and touch controls of at least 48 dp. The app starts with an empty personal workspace and contains no sample vacancies or seeded identity.

## Product behavior

- Create a private phone profile and pick the exact PDF résumé through Android's document picker.
- Save employer links from any country or profession, with searchable role/company/location details.
- Pair a configured HTTPS service with a one-time code. The bearer session and local drafts use AES-GCM with Android Keystore; no plaintext preferences or backups.
- Select synced opportunities, supply separate employer messages and explicit undecided/yes/no data-processing and future-contact choices.
- Review the server's immutable profile fields, résumé name/size/SHA-256 and per-job readiness before pressing **Approve and Auto Apply**.
- Stop pending work, review exact outcomes, export redacted receipt evidence, and reopen an earlier rate-limited plan for deliberate review after cooldown.
- Only confirmed **live** Lever receipts with an application ID count as verified applications. Test/unknown/uncertain records are visibly separate.

Opening an employer link does not submit or create a receipt. Missing connectors, unknown requirements or unsupported custom questions remain manual applications. The phone does not hold an employer API key and does not drive third-party login pages.

Phone-only drafts and connected workspaces have separate encrypted storage identities. Pairing does not silently upload an offline profile. Tokens expire; revocation preserves server records. The service must be reachable to revoke an active token.

## Build

Use JDK 21 (JDK 17 also meets AGP's baseline) and Android SDK Platform 36. AGP selects Build Tools 35.0.0 for this pinned project. Set the SDK path in an untracked `local.properties` or `ANDROID_HOME`.

```sh
./gradlew --no-daemon --max-workers=2 :app:assembleDebug :app:lintDebug
bash checks/run-policy-checks.sh
```

The checked-in wrapper is generated by official Gradle 8.13 and checks the distribution SHA-256. Pinned dependencies: AGP 8.13.2, Kotlin and Compose compiler plugin 2.3.10, Compose BOM 2025.10.01, Activity 1.11.0, Lifecycle 2.9.4. Minimum phone version: Android 8 / API 26. Debug package: `com.saleh.careerfinder.preview`. Release package: `com.saleh.careerfinder`; release signing is not configured.

## Connect a phone

Configure the backend's explicit HTTPS origin and a TLS gateway preserving that exact Host. The server listener can stay on loopback behind the gateway. Generate a five-minute pairing code using the service's private pairing CLI, then enter the origin and code on the phone. The app deliberately rejects HTTP, redirects, embedded URL credentials, invalid certificates and an origin containing a path/query/fragment. It has no trust-all or emulator cleartext override.

The local Node service's existence alone does not make it reachable from a phone. No hosted gateway, production employer credential or live submission is installed by this Android source.

## Verification

The delivered source passed the official Gradle wrapper's `assembleDebug`, `lintDebug`, and `assembleDebugAndroidTest` tasks on an isolated macOS ARM toolchain. Lint reported zero errors and six dependency/idiom advisories. Three instrumented tests passed on a dedicated Android 16 / API 36 ARM emulator using the Pixel 7 profile. The exact build inputs, APK hashes, commands and limitations are recorded in [checks/verification.json](checks/verification.json); build and instrumentation output accompany it. This is a locally debug-signed preview, not a store release or a physical-device acceptance claim.

`checks/run-policy-checks.sh` executes the actual Java policy used by the app: secure URL construction, workspace isolation, PDF bytes/size/name, hashing, and strict live receipt counting. It makes no network requests.

The instrumentation tests are intended for a dedicated blank acceptance emulator:

```sh
./gradlew --no-daemon --max-workers=2 :app:connectedDebugAndroidTest
```

They exercise empty states, the connection requirement, encrypted phone-profile persistence across recreation, and Keystore record encryption/AAD isolation. They use fixture data only and never contact an employer. Build/instrumentation results must be reported from actual execution; source existence is not device-validation evidence.

Before release, verify large font sizes, TalkBack reading/focus, RTL, keyboard and document-picker return, rotation/recreation, offline behavior, lost/stale pairing, stored-record corruption, exact review/cooldown recovery, and a configured HTTPS connection. Physical-device acceptance, live authorized provider acceptance, production privacy/support information, store signing and store review remain separate.
